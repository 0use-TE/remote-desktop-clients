# 共享文件夹 · 0.1.17 本地测试版

## 使用

连接 Windows 后，打开会话齿轮 → **共享文件夹**。
也可以从 OuseRDP 的设置进入，断开连接后仍能管理目录里的内容。

Windows 在“此电脑”中显示名为 **OuseRDP** 的重定向共享盘。
直接打开 `\\tsclient\OuseRDP` 也可以；安卓页面顶部的 Windows 路径可以点击复制。
共享盘会在本版创建的新连接和重连时挂载，电脑无需另装文件传输程序。
如果 Windows 禁用了驱动器重定向，需要先在服务端允许该功能。

- **安卓 → Windows**：点击“添加文件”多选，或“添加文件夹”选择整个目录。
  复制完成后，内容会出现在 Windows 的 OuseRDP 共享盘中，可以继续复制到电脑其他位置。
- **Windows → 安卓**：在 Windows 把文件、视频或整个文件夹复制进共享盘。
  等资源管理器复制结束，在安卓共享文件夹页面点击“刷新”，勾选内容，点击“保存到平板”，
  选择目标目录，例如“下载/电脑文件”。
- 点击目录名称进入，勾选框用于选择整个目录。文件和文件夹都支持批量保存。
  “返回上一级”和安卓返回手势均可返回父目录。

添加和保存会复制内容。共享目录里的修改不会自动同步回最初选择的安卓文件夹。
图片、视频按文件原样复制，不解码或转码；空目录和子目录结构保留。
同名内容会另存为带编号的副本，不覆盖已有内容。
跨 Windows/Android 不合法的文件名字符会替换，超长名称会缩短并尽量保留扩展名。

## 传输行为

- 安卓导入/导出在独立后台线程中按 128 KiB 分块复制，使用 64 位大小计数；
  不把整个视频装入内存，也不经过图片剪贴板。
- 安卓页面显示本地导入/导出的进度和取消按钮。Windows 与共享盘之间的网络复制进度由
  Windows 资源管理器显示。复制中的文件应等写入完成后再导出；检测到长度或修改时间变化会中止该副本。
- 导入先写入共享盘外的工作目录，完整后通过非覆盖的原子重命名发布。
  旧内核或文件系统不支持该操作时，回退到独占创建和分块复制。
- 取消或失败会清理当前根项目的临时副本；此前已经复制完成的项目保留。
  云端/外置存储提供方拒绝清理时可能留下部分导出内容，需要在目标目录检查。
- 离开文件页面不会主动取消任务；已有 RDP 前台服务继续管理连接。
  应用进程被系统结束后不自动续传。下次导入会清理应用工作目录中遗留的暂存内容。

系统文件/目录选择器只授权选中的内容，不申请全盘访问权限。
Windows 映射的是应用的专用 `OuseRDP-Shared` 目录，其余应用文件和暂存目录不在共享盘中。
共享目录属于应用空间，卸载应用会移除；要保留的内容请先“保存到平板”。

## 实现与验证

连接参数解析后、FreeRDP 预连接加载通道前，通过原生设置 API 注册一个
`RDPDR_DTYP_FILESYSTEM` 设备，名称为 `OuseRDP`，启用 DeviceRedirection。
不启用自动导出所有驱动器，不修改忽略的上游依赖源码；其他客户端保留原来的连接流程。
安卓导入/导出使用 SAF DocumentsContract，不依赖将 content URI 转换成物理路径。

主机测试覆盖目录/视频字节往返、空目录、中文名称、同名保留、取消和失败清理、
写入中源文件、短读、未知长度、超过 2 GiB 的合成流、共享目录边界、连接配置时序，
以及大小屏布局、选择和目录导航。SAF 测试通过 DocumentsProvider 的实际文档接口完成往返复制。

独立 ARM64 原生测试在平板上验证 RDPDR 配置和 Download 所在文件系统的原子发布、
中文/emoji 路径、同名内容保留，并复核已有显示与图片剪贴板桥接行为。
该测试不连接 Windows，不安装或修改主应用。

实际 Windows 挂载、双向大视频/整个目录复制、服务端权限和长时间后台传输，仍需用户安装后验收。
APK 仅构建和传送，由用户手动安装；本版不发布 GitHub Release。

参考：[Android 文件与目录选择器](https://developer.android.com/training/data-storage/shared/documents-files)、
[RDP 文件系统通道](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpefs/)。
